TarCite Citation Suggestion Pipeline

From user paragraph to ranked citation suggestions — 7-stage enhanced retrieval

Phase 1 — Document Ingestion (one-time setup)
PDF Scanning
Scan directories for PDF, RIS, BibTeX. Extract full text & metadata via PyMuPDF + Crossref API.
PyMuPDF
Text Chunking
Sentence-aware splitting: ~900-char chunks, 200-char overlap. Abstract + notes + fulltext.
Custom chunker
Dual Indexing
Embed chunks into vectors (ChromaDB) + index text for keyword search (FTS5). Store metadata in SQLite.
ChromaDB + FTS5
Phase 2 — Citation Suggestion (per query)
0
User Paragraph
Researcher pastes an academic paragraph and clicks "Suggest Citations". The app searches their local library for relevant sources.
1
HyDE — Hypothetical Document Embeddings
The LLM generates a 2-4 sentence hypothetical ideal cited passage that a relevant source might contain. This passage is embedded and used as the vector search query — bridging the vocabulary gap between user language and academic paper language. Falls back to raw paragraph on failure.
LLM (any provider) +10-20% recall
2
Parallel Triple Retrieval
Three search strategies run concurrently via ThreadPoolExecutor:
Vector Search
Cosine similarity between HyDE query vector and all chunk vectors in ChromaDB. Catches conceptual similarity.
ChromaDB HNSW
BM25 Keyword
BM25 ranking with Porter stemming over FTS5 index. Catches exact term matches like "CRISPR-Cas9".
SQLite FTS5
Title Search
Keyword matching against paper titles. Papers with title matches get a 2x weight boost in fusion.
SQLite LIKE 2x weight
3
Weighted Reciprocal Rank Fusion (RRF)
Merge three ranked lists using weighted RRF: score = sum of weight / (k + rank). Title stream gets 2x weight. Chunks are grouped by paper — keeping the best 6 chunks per paper — and enriched with SQLite metadata. Papers found only via title are included with their abstract as evidence.
RRF k=60 Title 2x
4
Cross-Encoder Reranking
A CrossEncoder model scores each (paragraph, evidence) pair jointly with full cross-attention — far more accurate than bi-encoder cosine similarity. Uses up to 1024 characters of evidence per candidate. Returns top-K candidates sorted by rerank score.
ms-marco-MiniLM-L-6-v2 1024 chars
5
MMR — Max Marginal Relevance
Ensures diversity in the final candidate set. Each candidate is scored: λ × relevance − (1−λ) × max_similarity_to_selected. With λ=0.7, the system balances 70% relevance with 30% diversity — preventing redundant suggestions (e.g., 5 papers all saying the same thing).
λ = 0.7 cosine diversity
6
LLM Evaluation & Anti-Hallucination
The top candidates are sent to an LLM with strict instructions: select relevant sources, extract verbatim evidence quotes, rate confidence (High/Med/Low), and rate evidence coverage (strong/partial/single_point). Every suggested item_key is validated against the retrieved source list — fabricated citations are silently removed. Invalid JSON triggers retry with stricter prompt + repair.
OpenAI-compatible Anti-hallucination
7
User Feedback (Thumbs)
Each suggestion shows thumbs up / thumbs down in the card header. Clicking an active thumb toggles it off. Feedback is persisted in SQLite per (run_id, item_key) and available for future ranking personalization.
SQLite persisted Toggle on/off
Ranked Citation Suggestions
Each suggestion includes: inline citation, full reference, verbatim evidence quotes,
confidence rating, evidence coverage, and reason for relevance.
