# TarCite Workspace — API Reference

Base URL: `https://api.ci-work.com`

All JSON requests must include `Content-Type: application/json`.
All API responses are JSON unless noted otherwise.

---

## Authentication

Every request to the chat proxy must include:

```
X-Device-ID: <device-uuid>
```

The device UUID is generated by the client (any valid UUID v4). Register it once before use.

---

## Endpoints

### 1. Register Device

Register a device UUID so it can use the API. Safe to call on every app launch — idempotent.

```
POST /register
```

**Body**
```json
{ "device_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" }
```

**Response 200**
```json
{
  "registered": true,
  "created": true,
  "daily_limit": 30,
  "requests_today": 0,
  "is_blocked": false,
  "credits_remaining": 0
}
```

- `created`: `true` on first registration, `false` on subsequent calls
- `daily_limit`: free requests allowed per day
- `credits_remaining`: paid credit balance (tokens)

---

### 2. Chat Completions

OpenAI-compatible chat endpoint. Streams the response.

```
POST /v1/chat/completions
X-Device-ID: <device-uuid>
```

**Body** — standard OpenAI chat format:
```json
{
  "model": "default",
  "messages": [
    { "role": "user", "content": "Hello" }
  ],
  "stream": true
}
```

**Response** — streams the upstream provider response directly (SSE for `stream: true`, JSON for `stream: false`).

**Response headers on success:**
```
X-CIWork-Provider: <provider-name>
X-Credits-Remaining: <integer>   ← only present when request was charged to credits
```

Credit deduction happens after the response completes, based on actual token usage.

---

### 3. Get Balance & Daily Limit

Returns the device's current credit balance and daily usage. Use this to show "requests remaining" in the UI.

```
GET /billing/balance
X-Device-ID: <device-uuid>
```

Or via query param (useful for links):

```
GET /billing/balance?device_id=<uuid>
```

**Response 200**
```json
{
  "tier": "free",
  "tier_usage": [
    { "group": "default", "used_today": 0, "daily_limit": 40 },
    { "group": "premium", "used_today": 0, "daily_limit": 10 }
  ],
  "credits_remaining": 0
}
```

| Field | Meaning |
|---|---|
| `tier` | Current plan name (e.g. `free`, `pro`) |
| `tier_usage` | Array of per-group usage objects |
| `tier_usage[].group` | Model group name (`default`, `premium`, etc.) |
| `tier_usage[].used_today` | Requests used today for this group (resets at midnight UTC) |
| `tier_usage[].daily_limit` | Max free requests per day for this group |
| `credits_remaining` | Paid credit balance in tokens (1 credit = 1 token). `0` when no credits purchased |

> If `credits_remaining > 0`, the device bypasses all daily free limits entirely and is billed per token instead.

---

### 4. Buy Credits — Initiate Checkout

Creates a Stripe Checkout session and returns the URL to redirect the user to.

```
POST /billing/checkout
```

**Body**
```json
{
  "device_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "amount_cents": 500
}
```

- `amount_cents`: amount in US cents. Minimum $3.00 (300 cents). Must be a whole-dollar amount (100, 200, 300 …).

**Response 200**
```json
{ "url": "https://checkout.stripe.com/..." }
```

Redirect the user to `url`. Stripe handles payment collection.

**Error responses:**
```json
{ "error": "amount_too_low", "message": "Minimum payment is $3" }
{ "error": "device_not_found", "message": "Device not registered" }
```

---

### 5. Buy Credits — Web Page (optional)

A hosted page that lets the user enter an amount and initiate checkout. Useful if you want to link out instead of building a custom UI.

```
GET /buy?device_id=<uuid>
```

Shows current balance, pricing info, and a payment form. Redirects to Stripe on submit.

---

### 6. Checkout Success / Cancel Pages

These are display-only pages Stripe redirects to after payment. Not useful as API endpoints.

```
GET /billing/success?session_id=<stripe-session-id>
GET /billing/cancel
```

> Credits are granted via Stripe webhook, not on the success page. The success page is purely informational.

## Rate Limit & Error Responses

All errors follow this shape:

```json
{
  "error": "<error_code>",
  "message": "<human-readable message>",
  ...extra fields
}
```

### Limit-hit responses

When a device hits its daily limit or runs out of credits, the response is:

**HTTP 429**
```json
{
  "error": "daily_limit_reached",
  "message": "Daily limit reached. Buy credits for unlimited access.",
  "limit": 30,
  "buy_url": "https://api.ci-work.com/buy?device_id=<uuid>"
}
```

If the device previously had credits but they are now exhausted:
```json
{
  "error": "daily_limit_reached",
  "message": "Your credits are exhausted. Buy more to continue.",
  "limit": 30,
  "buy_url": "https://api.ci-work.com/buy?device_id=<uuid>"
}
```

Always show `message` to the user and open `buy_url` if they want to top up.

### Other error codes

| Code | HTTP | Meaning |
|---|---|---|
| `missing_device_id` | 401 | `X-Device-ID` header missing |
| `device_not_registered` | 403 | Device UUID not registered |
| `device_blocked` | 403 | Device has been blocked by admin |
| `group_not_allowed` | 403 | Model group not available on this tier |
| `model_not_configured` | 502 | No active provider for requested model |
| `invalid_json` | 400 | Request body is not valid JSON |
| `invalid_device_id` | 400 | `device_id` is not a valid UUID |

## Credit Pricing

| Unit | Value |
|---|---|
| 1 credit | 1 LLM token |
| 1 dollar | 2,000,000 credits (~100 requests at ~20K tokens/request) |
| Minimum purchase | $3.00 |

> These values are configurable by admin via the dashboard — always fetch current rates from `GET /billing/balance` rather than hardcoding.

---

## Typical App Flow

```
1. App launch
   └─ POST /register  (with stable device UUID)

2. Every session / periodically
   └─ GET /billing/balance  → show credits & daily usage to user

3. Send message
   └─ POST /v1/chat/completions  (with X-Device-ID)
      ├─ success → stream response to user
      └─ 429 → show message + buy_url button

4. User taps "Buy Credits"
   └─ POST /billing/checkout  → get Stripe URL → open in browser/webview
      └─ on return, call GET /billing/balance to refresh balance
```
